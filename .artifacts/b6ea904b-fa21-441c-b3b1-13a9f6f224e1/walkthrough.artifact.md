# 施設検索の安定化と精度向上、およびファイル分割の完了

Google マップでは結果が出るのにアプリで「該当なし」になる問題を完全に解決し、同時にプロジェクトのメンテナンス性を高めるためのファイル分割を実施しました。

## 変更内容

### 1. 住所正規化とエリア判定の最適化 (`order_form_screen.dart`)
- **ハイフン保護:** 住所正規化において「ハイフン `-`」を維持するように修正しました。これにより「1-1」などの番地を正確に照合できるようになりました。
- **店名・住所の同時照合:** 指定エリア名（町名など）が住所に含まれていなくても、店名（例：○○町クリニック）に含まれていればヒットするように判定を柔軟化しました。
- **救済措置（フィルター解除）:** 厳密な絞り込みにより 0 件になった場合、SnackBar から「フィルター解除（全表示）」を実行できる仕組みを導入しました。

### 2. 強制 API 検索の確実な連動
- サイドバーの「Googleマップで再検索」ボタンが、ローカルDBの結果の有無に関わらず、確実に最新の API データを取得・学習（DB保存）するようにロジックを修正しました。

### 3. ステップ別ウィジェットの細分化 (`lib/screens/order_form/widgets/steps/`)
肥大化していた `step_widgets.dart` を、機能ごとに独立した 6 つのファイルへ分割しました。
- 各ステップが自身の責務に集中できる構成になり、今後の機能拡張やバグ修正が容易になりました。
- 循環参照やインポート漏れをすべて解消し、ビルドの安定性を確保しました。

## 解決された課題
- **検索の不一致:** Google 側の柔軟な住所フォーマットを許容しつつ、指定エリア内の施設を漏れなく抽出可能になりました。
- **再検索の不備:** 「該当なし」ボタンが名実ともに機能し、未知の施設を確実にDBへ追加できるようになりました。
- **メンテナンス性:** 巨大ファイルが解消され、コードの可読性が大幅に向上しました。
