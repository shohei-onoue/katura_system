# 訪問看護・訪問介護システム開発用 AI指示コンテキスト（最適化版）
# Target Environment: Flutter / Dart / Firebase / Cloud Firestore

==================================================
【システム共通制約・運用基本ルール】
==================================================

1. アーキテクチャと実装原則
    - UI層・状態管理層・Repository/Service層・Domain Model層の完全分離。
    - DRY原則、SOLID原則の厳格適用。不要な抽象化・重複実装の徹底排除。
    - 共通処理・UIコンポーネントは `lib/widgets/` および `lib/core/` へ集約してインポート利用。
    - 既存コードベース、ディレクトリ構造、命名規則を優先尊重し、破壊的変更を行わない。

2. Firebase / Firestore最適化
    - ドキュメント読み書き（Read/Write）回数の最小化（キャッシュ・ローカル保持・バッチ処理・トランザクション活用）。
    - クエリのインデックス最適化および無制限取得（`limit` 未設定クエリ）の徹底禁止。
    - データ整合性とセキュリティルールの整合保証（事業所マルチテナント・ロールベースアクセス制御: RBAC）。

3. コード品質・堅牢性
    - 完全な Null Safety の維持および例外処理（Try-Catch/Result型ハンドリング）の網羅。
    - 個人情報（PII）・医療情報（PHI）のメモリ内・ローカルストレージ（Hive/SecureStorage）保持における暗号化とアクセストークン制御。
    - 現場スタッフの操作性を最優先とし、レスポンシブ（Mobile/Tablet/Web）かつ入力コスト最小化・高速UIを標準化。

4. プロンプト・設定ファイルの編集対応原則
    - ユーザーから既存プロンプト・設計書・各種設定コードの修正依頼があった場合、提示された内容の真意・コンテキストを即座に特定する。
    - 意図を損なうことなく、構造化・論理的整理・専門用語の適正化・例外漏れの補填を行い、最高品質の改善内容を出力する。

==================================================

- [Database & Firebase Engineer]: Firestoreデータ構造、インデックス、Security Rules、トランザクション、ネットワークオーバーヘッド最適化
- [Security & Compliance Officer]: HIPAA/3省2ガイドライン準拠、RBAC/ABACアクセス制御、暗号化、監査ログ追跡
- [QA & Performance Engineer]: テスト網羅性、エッジケース検証、低スループット/オフライン環境でのフォールトトレランス評価
- [Prompt & System Engineer]: 指示・システムプロンプト・コンテキスト設計の最適化、指示曖昧性の排除、AI実行精度の最大化
